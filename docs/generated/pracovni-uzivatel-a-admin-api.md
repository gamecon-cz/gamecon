# Pracovní uživatel a admin API

TL;DR: Pracovní uživatel je účastník, se kterým organizátor v adminu pracuje: moduly mu ukládají platby, ubytování, role nebo osobní údaje a admin API za něj přihlašuje na aktivity a spravuje tým. Vybrat si ho smí jen přihlášený s právem stránky, která s ním pracuje (infopult, ubytování, práva, finance, peníze), přihlašovat ho na aktivity jen infopult. Admin API i zvláštní stránky adminu (program účastníka, reporty) jsou jen pro toho, kdo v adminu smí aspoň jednu stránku, kromě výslovných výjimek; omnibox jen pro toho, komu ho admin nabízí.

## Vstupní body

- `model/Admin/PracovniUzivatel.php`: kdo smí (`PRAVA`, `isPovolen()`), kdo za něj přihlašuje na aktivity (`PRAVO_PROGRAMU`, `isPovolenProgram()`), jediné čtení ze session (`zSession($u)`), ID z formuláře nebo odkazu (`parseId()`)
- `admin/scripts/prihlaseni.php`: zrušení (POST `zrusitUzivateleProPraci`), výběr (POST `vybratUzivateleProPraci` + `id` z omniboxu, GET `?pracovni_uzivatel=` z odkazů), načtení do `$uPracovni`
- `admin/index.php`: `$maPristupDoAdminu` hned po přihlášení, jednou pro API i zvláštní stránky; blok `$stranka === 'api'`: odmítnutí `401`/`403 {"error": …}` ještě před načtením endpointu; `$zvlastniSkript` a `$smiZvlastniStranku`: zvláštní stránka, odmítnutému stránka 403; blok `all.uzivatel`: výběr uživatele v liště
- `model/Admin/PristupDoAdminu.php`: „smí v adminu aspoň jednu stránku“ (`PRAVA`, `isPovolen()`) a zvláštní stránky i bez přihlášení (`VEREJNE_STRANKY`)
- `model/Admin/OmniboxAdminu.php`: kdo smí omnibox (`isPovolen()`) a koho mu najde (`getRoleHledanych()`), použité v `admin/index.php` i `admin/scripts/zvlastni/ajax-omnibox.php`
- `model/Admin/ApiAdminu.php`: výjimky (`BEZ_PRIHLASENI`, endpoint => důvod), rozhodnutí 401/403 (`getKodOdmitnuti()`) a odpověď s ním (`odmitni()`)
- `admin/scripts/api/*.php`: endpointy; většina jen předává na `web/moduly/api/<x>.php`, `aktivitaAkce` a `aktivitaTym` napřed odmítnou operátora bez `PRAVO_PROGRAMU`, který má pracovního uživatele
- `admin/scripts/.htaccess`: soubory skriptů adminu nejdou otevřít přímo, jen přes `admin/index.php`
- `model/Admin/FormularPracovnihoUzivatele.php`: formulář uloží změnu jen tomu, u koho se načetl (přepnutí v jiné záložce)
- `ui/src/api/program/index.ts`, `odpověďAkce()` a `fetchAktivitaTým()`: UI programu bere neúspěšný HTTP status akce i načtení týmu jako chybu s hláškou

Testy: `tests/Admin/PracovniUzivatelTest.php`, `tests/Admin/ApiAdminuTest.php`, `tests/Admin/PristupDoAdminuTest.php` (i že každé právo z hlaviček modulů je v `PristupDoAdminu::PRAVA`), `tests/Admin/OmniboxAdminuTest.php`, přes skutečný Apache `tests/web/PracovniUzivatelVAdminuTest.php` a `tests/web/PristupDoApiAdminuTest.php` (ten projde všechny soubory v `admin/scripts/api/` i v `admin/scripts/zvlastni/`, takže nový endpoint nebo zvláštní stránka bez výjimky je automaticky jen pro admin, a že žádný skript z nich nejde otevřít přímo), kapitán jako pracovní uživatel a chyby týmového API jako JSON `tests/web/AktivitaTymApiTest.php`, v UI `ui/src/api/program/odpověďAkce.test.ts`.

## Pravidla

- **Pracovního uživatele jen s právem stránky, která s ním pracuje** (`PracovniUzivatel::PRAVA`): Infopult (100), Uživatel (101), Práva (106), Finance (108), Peníze (111). Stejnému okruhu admin nabízí výběr uživatele. `(záměr)` Stránky Finance, Peníze a Práva bez pracovního uživatele nefungují a odkazy `?pracovni_uzivatel=` z e-mailů a reportů (třeba nespárovaná platba pro CFO) vedou na Uživatele. Dřív právo infopultu stačilo jen proto, že ho všichni členové rolí CFO a SEF_INFOPULTU měli přes jinou roli, a to se může změnit.
  - Kdo právo nemá, tomu se výběr nezpracuje: POST i odkaz dostanou hlášku a přesměrování, odkaz bez parametru. Klíč pracovního uživatele se mu ze session zahodí při každém požadavku, i ten nastavený před přihlášením nebo před ztrátou práva (přepnutí na jiného uživatele), aby se po dalším přihlášení nevrátil.
  - Pracovního uživatele čti jen přes `PracovniUzivatel::zSession($u)`, ne `Uzivatel::zSession(Uzivatel::UZIVATEL_PRACOVNI)`: pravidlo pak platí i tam, kam `prihlaseni.php` nedosáhne nebo kde se čte dřív.
  - Neplatné ID (chybí, pole, text) nebo neexistující uživatel: hláška „Uživatel pro práci nenalezen“, žádný TypeError.
- **Přihlašovat pracovního uživatele na aktivity a spravovat jeho tým smí jen infopult** (`PracovniUzivatel::PRAVO_PROGRAMU`). `admin/scripts/api/aktivitaAkce.php` a `aktivitaTym.php` operátorovi bez něj, který pracovního uživatele má, odpoví `403 {"error": …}`; bez pracovního uživatele jedná za sebe. `Aktivita::prihlasovatkoZpracujBezBack($uPracovni, $u)` totiž nekontroluje, jestli operátor smí jednat za účastníka, a přihlašuje s jeho příznaky (třeba na dosud neotevřené). Stránka Uživatel (101) přesto nabízí odkaz Program, ten ale jen ukáže program a akce skončí hláškou o oprávnění.
- **Admin API běží za pracovního uživatele, operátor zůstává operátorem.** Wrappery nechávají `$u` (přihlášený, jeho práva a role) a webové API bere účastníka z `$uPracovni`, bez něj jedná přihlášený sám za sebe: `aktivitaAkce` a `aktivityUzivatel` přes `$uPracovni ?? $u`, `aktivitaTym` přes `isset($uPracovni)`, `prihlasenyUzivatel` vrací `{ucastnik: $uPracovni ?: $u, operator: $u}` (`Uzivatel::apiPrihlasenyUzivatel()`, globály).
  - `aktivitaAkce` vrací v `aktivitaUzivatel` stav přihlášení, slevu a `vedu` účastníka, ne operátora: UI to hned zapíše do programu pracovního uživatele.
- **Admin API i zvláštní stránky jen pro toho, kdo v adminu smí aspoň jednu stránku**, tedy má některé z `PristupDoAdminu::PRAVA` (stejná podmínka jako přepínač vzhledu). Rozhoduje seznam práv, ne hlavičky modulů: ty by se na každý požadavek API četly ze zhruba dvaceti souborů. Že seznam pokrývá každé právo z hlaviček (i podstránky jen pro Loga, 112), hlídá test; nová stránka s novým právem ho musí doplnit. Nepřihlášený dostane od API `401`, přihlášený bez přístupu (účastník bez práv) `403`, obojí jako JSON `{"error": …}`. Zvláštní stránka (`admin/scripts/zvlastni/`, bez rámu adminu) nepřihlášenému ukáže přihlášení a účastníkovi bez práv stránku 403; dřív stačilo přihlášení a omnibox vydal komukoli e-maily, telefony a zůstatky. Bez přihlášení i bez práv jdou jen `PristupDoAdminu::VEREJNE_STRANKY` (`program-obecny`, `last-minute-tabule`). Reporty, online prezence a potvrzení rodičů hlídají svá práva ještě samy. Výjimka z API musí být v `ApiAdminu::BEZ_PRIHLASENI` i s důvodem a endpoint pak přístup hlídá sám:
  - `preview-vstup`: brána preview potřebuje od nepřihlášeného `401 {"stav":"neprihlasen"}`, bez tokenu brány vrací 404, viz [preview-vstup-pres-adminu](preview-vstup-pres-adminu.md).
  - `programManifest`: veřejná data. Volá ho `program-obecny`, kterou admin otevře i bez přihlášení.
  - `program-obecny` volá nepřihlášeným i `aktivityUzivatel` a `prihlasenyUzivatel`. Dostane 401 a UI to snese, program se vykreslí bez údajů o uživateli.
  - Brána nekontroluje práva konkrétní funkce: endpoint, který vrací nebo mění víc, než smí každý organizátor, hlídá práva sám (`obchod-mrizky-view`, `reload-fio`).
- **Omnibox (`ajax-omnibox`) jen tomu, komu ho admin nabízí** (`OmniboxAdminu`), ne každému, kdo v adminu něco smí: vydá e-maily, telefony a zůstatky kohokoli, a vypravěč s Moje aktivity nebo správce log je vidět nemá. Smí ho, kdo má některé z `PracovniUzivatel::PRAVA` (výběr uživatele, Infopult, Finance) nebo Reporty (104), kdo se smí přepnout na jiného uživatele (`muzePrepnoutNaJinehoUzivatele()`, právo 114) a infopulťák (role LETOSNI_INFOPULT); tomu, nemá-li jiné z těch práv, najde jen vypravěče a partnery, na které se smí přepnout (`getRoleHledanych()` přebije `jenSRolemi` z požadavku). Stejný okruh vidí pole Přihlásit se jako, jinak by mu omnibox odpovídal 403 a přepnutí potichu nefungovalo. `(záměr)` Na locale se smí přepnout každý, a tak i omnibox smí každý; webové testy běží na locale, a proto pravidla omniboxu ověřuje jen `OmniboxAdminuTest` s mocky.
- **Akce v UI programu s neúspěšným statusem je chyba.** `fetchAktivitaAkce` a `fetchAktivitaTymAkce` převedou 401/403/5xx i prázdné nebo nečitelné tělo na `{úspěch: false, chyba: {hláška}}`; jinak by tělo `{error}` bez `chyba` prošlo jako úspěch. `fetchAktivitaTým` (GET) při neúspěšném statusu vyhodí `ChybaApi` s hláškou (u 404 z těla), modal ji ukáže a bez načtených dat se zavře; jinak by odpověď bez týmu vypadala, že uživatel tým nemá.
- **Webové `aktivitaAkce` a `aktivitaTym` odpoví nepřihlášenému `401 {"error": …}`**, ne prázdnou dvoustovkou, kterou by program nepřečetl (vypršelé přihlášení na webu). V adminu ho odmítne už brána API.
- **Odkaz s `?pracovni_uzivatel=` projde přihlášením.** Nepřihlášenému parametr zůstane v adrese, formulář přihlášení se odešle na tutéž URL a po přihlášení `back()` vrátí na `REQUEST_URI`. Výběr proběhne v dalším požadavku. Totéž po `?gcsso=`, viz [odkazy-do-archivnich-rocniku](odkazy-do-archivnich-rocniku.md).
- **Tým (`aktivitaTym`) je vždy přihlášeného, resp. pracovního uživatele.** GET parametr `uzivatelId` nečte, neexistující aktivita dá `404 {"chyba": …}`. Akci s týmem provede jen kapitán, tedy pracovní uživatel, ne operátor.
- **Skripty adminu jen přes `admin/index.php`.** `admin/.htaccess` přepisuje na `index.php` jen adresy bez přípony, takže `admin/scripts/api/<endpoint>.php` by jinak běžel přímo, bez zavaděče a bez kontroly přihlášení a práv. `admin/scripts/.htaccess` (`Deny from all`, jako `admin/cron`) ho odmítne 403.

## Gotchas

- `apiPrihlasenyUzivatel()` čte `$u` a `$uPracovni` jako globály. Admin API načítá endpointy v globálním scope `admin/index.php`, takže přiřazení `$u = …` ve wrapperu změní i operátora, kterého API vrátí. Proto ho wrappery nedělají.
- Bez pracovního uživatele je v adminu účastníkem přihlášený sám (`ucastnik.id === operator.id`), ne `null`. Testy podle shody poznají, že pracovního uživatele nemá.
- Lokálně lze nepřihlášené API ověřit curlem s prázdnou relací. Testy v `tests/web/` posílají cookie testovací DB, takže nezasahují do dev DB.
- POST na veřejný web bez hlavičky `Referer` z téhož webu zahodí `omezCsrf()` jako `404 Stránka nenalezena`, dřív než se načte modul. Test webového API ji proto musí poslat (`CURLOPT_REFERER`), admin to nedělá.
